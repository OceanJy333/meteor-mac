# 调试与自动验证

目标：不靠人点，也能确认“进得去、看得到、能操作”。

## 必备工具（参考实现都有）

| 工具 | 用法 | 解决什么 |
|---|---|---|
| 脚本化输入 | `METEOR_SCRIPT=script.json`，内容如 `[[18,"move",140,153],[21,"down"],[21.3,"up"],[44,"key",87,1],[48,"key",87,0]]`（秒、动作、参数；按键用 VK 码） | 无人值守地点菜单、走路、攻击 |
| 定时截图 | `METEOR_SNAP=2` 每 2 秒存一张 `logs/snap-NNN.png`，GL 后缓冲全分辨率读出 | 看真实画面，而不是猜 |
| 实时状态 | `logs/live.json`：运行秒数、各 API 调用次数、堆、错误 | 卡住时看在反复调什么 |
| 崩溃现场 | 出错时打印最近 15 次 API、寄存器、栈上 16 个值、寄存器指向的 COM 对象、EIP 处反汇编 | 定位虚表槽位、参数个数错误 |
| 全量 API 日志 | `--verbose` | 少用，很慢 |
| 地址追踪 | `METEOR_TRACE=0x...,0x...` | 和 REA 静态分析对照 |
| 段错误 | `PYTHONFAULTHANDLER=1` | C 层崩溃时看 Python 调用栈 |
| 原生性能 | `sample <pid> 5` | 时间花在 Python、Unicorn 还是 GL |
| 声音 | `METEOR_AUDIO_DUMP=out.raw` 导出混音（float32 立体声） | 不用耳朵也能确认有声音 |

## 写脚本的方法

1. 先跑一次只截图，从截图量出按钮坐标（游戏坐标系，如 640×480）。
2. 点击前先 `move` 到目标，再 `move` 偏 1 像素，再 `down`/`up`。有的菜单要先收到悬停才响应点击。
3. 时间留余量：菜单加载慢，点早了不生效。不确定时看截图里的计时器或界面状态。
4. 每个关键状态一个脚本：`script-menu`（进选关）、`script-play`（进关卡、移动、攻击）、`script-exit`（Esc → 确认 → 回菜单 → 退出）。

## 自动验证做不到的

- 窗口能不能真正显示在屏幕上：截图读的是 GL 缓冲，窗口没上屏也能截到。**打包后从 Finder 双击一次。**
- 真实触摸板手势：程序模拟的滚动事件进不了窗口。
- 系统按键（⌘Q）、标题栏按钮：脚本发不了。

这些明确列给用户试。

## 性能排查顺序

1. 打印每 120 帧的平均帧时间和最差帧时间。
2. `sample` 看原生栈：
   - Python 解释器占大头 → 找热点 API，先优化 Python，再搬 C。
   - Unicorn `store_helper` / `notdirty_write` / `tb_invalidate` → 模拟器自身开销。先确认没有自修改代码（对 `.text` 挂写钩子，统计放 C 里），排除后通常只能接受。
   - GL 驱动 → 检查是不是每帧在上传或回读整块贴图。
3. 周期性卡顿先试 `gc.freeze()`。
